(`plans/investigations/evidence/readme-knowledge-lineage-audit/imported-knowledge-source-comparison.json`, produced at `88f00145e`, three commits behind the session's starting HEAD) reconfirmed against real source that the defect was still live: `_file_evidence_corroboration` only checked that a cited file existed, never its content or polarity.

**K1** (`d11ac3800`, `fix(facts): qualify imported knowledge per claim`): new `facts/knowledge_evidence_verification.py` resolves a claim's cited `file`/`source_file` evidence safely inside the pinned clone (rejecting traversal/outside-root/missing/unreadable paths) and classifies the cited Python region via an innermost-function AST stub check (reusing `python_evidence_polarity.py::function_is_unimplemented`'s proven `raise NotImplemented*` idiom), with a class-wide public-method fallback for claims cited at a class-declaration line. A positive capability claim whose cited implementation is a stub is now a genuine conflict (rejected, never selected), matching the existing SPDX-mismatch precedent; the mirror limitation claim citing the same stub stays corroborated. Verified against the real 3D FBX (`FbxExporter.save`/`save_to_stream`) and Barcode PDF (`PdfRenderer.render`) false positives the audit found, and against the real COLLADA case (`ColladaExporter`, genuinely implemented, correctly stays corroborated) as the public/internal-distinction regression guard. Also removes the field-level `verified_any` aggregate-laundering defect: a field whose selected items are a genuine mix of verified/unverified now emits two `FactRecordV2` records (a verified-authorizing one under the unchanged `aspose-knowledge` qualifier, and a separate non-authorizing `aspose-knowledge-supporting` one) instead of one record whose `verified` state one item could earn for its unverified siblings — the resolver's existing precedence rules (`resolution.py`) already pick the verified record as the field's sole authorizing fact, so no downstream consumer needed changes.

**K2** (`872abdd04`, `fix(facts): separate public API presence from capability`): separates five previously-conflated concepts for API knowledge — symbol exists, is publicly reachable, has a signature, is implemented, authorizes capability prose. `curated_python_api_ast.py::member_is_implemented` classifies a resolved method/function AST node as real or a proven stub, wired into `curated_python_api_projection.py`'s per-member catalog rows as a new `implemented` field; `verified_template_api_members.py`'s renderer now withholds "Supports .../Converts .../Renders ..." prose for a proven stub (confirmed against the real 3D `NurbsSurface.to_mesh`, which genuinely raises `NotImplementedError`) while keeping it discoverable with its exact signature, and excludes it from a class's "Supports ..." summary sentence. A new `readme/claim_map_capability_validation.py` adds a deterministic, renderer-independent defense-in-depth check into `validate_readme_document_candidate`, rejecting any `api.public_surface` claim binding that carries capability wording for a member the run's own facts prove is a stub, regardless of which generation path produced it. Separately, `aspose_detectors.py::detect_api_public_surface` no longer hard-requires the imported corpus's `reachable` field — direct inspection of the real 3D (uniformly `False` for all 327 entries), Note (entirely absent), and Barcode (entirely absent) bundles confirmed it is never a discriminating signal, so requiring it unconditionally rejected all three bundles regardless of real visibility; reachability now resolves from the corpus's own visibility vocabulary (public/exported vs. conventional/internal/private, normalized across the three real schema variants) with a name-convention fallback when absent, recovering 184/28/146 real classes respectively. Also fixes `composer_factpack.py`'s `classes` value from a `{name: {...}}` dict to the list of dicts every real consumer (`verified_source_detail_routing.py`'s `isinstance(classes, list)` gate, among others) already expected, corrects the kind-to-module mapping for the corpus's real `class_definition`/`function` kind strings (previously always fell through to the default), and stops silently emptying bare top-level `function`-kind entries (which carry their own params/return_type, not nested under "methods"). `aspose_knowledge_selection.py`'s blanket rejection of `api`/`api_class`/`api_method`/`api_field` claims as "covered by the structured API surface" is now conditional on that surface actually existing and being non-empty for the family/platform — when it doesn't, these claims flow through the same selection/corroboration pipeline as every other kind instead of silently disappearing as falsely "covered".
