- [master requirements verified-portfolio] **2026-08-08 — Added a typed TaskExecutionFocusV1 guard binding bounded canaries to the current claim and expanded the presentation brand contract to template v1.16.0.** This 167-file feature commit revises two existing decisions in place (no new decision numbers) and two existing requirements. Decision #97 is rewritten from "the agent evaluates tactics instead of following them literally" to "visible delivery is bound to one mechanically enforced execution focus": every active visible-delivery task must declare one immediate outcome, exact repository scope, permitted change classes, and retry/stall budget, and a bounded canary must bind to the current graph hash, active task, unexpired observer-owned claim, repository scope, and admitted approach before any preflight/clone/LLM work starts. Decision #98 is rewritten from the old "Aspose.3D first, Note second" ordering to "Python delivery follows current evidence through separate repository goals": PDF, Page, Note, and Aspose.3D each get their own goal id, and durable evaluation regresses a closed repository to `REGRESSED` when its evidence goes stale and no pending repository-specific refresh already owns it. The implementation is the new `supervisor/mission_execution_guard.py` (`TaskExecutionFocusV1`, covered by the new `tests/unit/test_mission_execution_guard.py`) plus `state/mission_goal_schema.py` additions, backing `plans/master.md`'s new "Small-goal execution and anti-drift" section and its six-item `DELIVERY-PY-*` small-goal catalog. Requirement `L8-054` is revised from `IMPLEMENTED` back to `PARTIAL`: live execution had proved a repository canary could bypass the active mission claim and keep running past the 15-minute retry budget, so the row now cites the concrete `TaskExecutionFocusV1`/`mission_execution_guard.py` fix and stays open until a real stale-claim canary is proven rejected then re-admitted after governed reclaim. Requirement `L8-041` is revised to encode the expanded `RepositoryPresentationBrandContractV1` (template v1.16.0): title-case Markdown headings, canonical uppercase visitor-facing abbreviations (PS/EPS/PDF/XPS/XLSX/HTML) while preserving exact package/path/API identifiers, a stricter Mermaid capability-graph shape (exactly one product-to-Core-capabilities connector, one or two balanced vertical capability columns, one Core-to-Outputs connector), a ban on public prose exposing internal source-revision/verification-status narration, and natural full-featured Enterprise Edition anchor text. Dozens of new `readme/`/`presentation/` modules back this (`public_text.py`, `public_vocabulary.py`, `verified_source_claim_matching.py`, `diagram_semantic_candidates.py`, `header_visual_layout.py`, `claim_accountability_candidate_policy.py`, among others), with roughly 30 test files updated or added.
