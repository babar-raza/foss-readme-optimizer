- [master governance] **2026-08-31 — logs/ coverage gap root-caused and mechanically closed: three-layer enforcement (pre-commit/CI block, push-triggered self-heal, daily full-history audit), replacing a convention no agent was mechanically held to.** User asked to investigate why `logs/` had missing daily entries and to plan a fix. A first pass proposed a pre-commit + CI blocking check; the user rejected it as still just a gate an agent can miss or bypass ("no agent could miss creating the logs -- this should be enforced") and asked for a production-grade, durable design instead.

**Investigation.** Full-history query (commit dates touching `plans/master.md`/`GOVERNANCE.md`/`requirements.md`/either decision-or-requirement `catalog.jsonl` vs. `ls logs/`) found 10 days with governed-file commits and no `logs/<date>.md` shard: 2026-08-01, 08-03, 08-04, 08-06, 08-08, 08-21, 08-22, 08-23, 08-25, 08-31. Every one of the 26 contributing commits carries `Co-Authored-By: Codex <noreply@openai.com>` -- decision #107 already grants Codex standing commit-and-push authority to this repo equal to Claude Code's, so this is a governance-model gap, not an unsanctioned actor. Confirmed live, not assumed: `gh api repos/:owner/:repo/branches/main/protection` returns `404 Branch not protected` -- `main` has no required status checks, so a red CI run has never been able to stop a bad commit from landing (`post_commit_push.py` already pushes before CI even starts). The one prior mechanical check, `check_logs_shard_index_consistency`, only verified `logs/README.md`'s table against files already present in `logs/` -- it had no concept of "a governed file changed, therefore an entry was needed," so a commit that never touched `logs/` at all was invisible to it. This pattern had already recurred four times before (2026-08-11 twice, 08-26, 08-27) and was only ever reactively backfilled, never fixed at the root.

**Fix -- three independent layers (decision #115), not one gate.**
1. `scripts/governance/validate_plan_structure.py`'s new `check_governed_edits_paired_with_log_entry` blocks a commit/push that edits a governed file with no paired `logs/` change in the same change (diffs working-tree-vs-`HEAD` locally, `before..after` in CI via `PLAN_STRUCTURE_DIFF_BASE`, wired through `ci.yml`). Wired into the same pre-commit hook and CI step `check_logs_shard_index_consistency` already used. Fixed a real, adjacent bug while building this: `_previous_master_md_text()`/the new `_read_file_at_ref()` needed explicit `encoding="utf-8"` on `subprocess.run(text=True)` -- Windows' default cp1252 was silently corrupting reads of this repo's UTF-8 content (em dashes, smart quotes) in a background reader thread whose exception never reached the caller, a false-negative risk for `check_wave_reconciliation_gate` too.
2. New `scripts/governance/log_shard_writer.py` extracts `append_log_entry.py`'s shard-formatting logic (shard header, entry/index-row building, shard-directory refresh) into one shared, importable implementation; `append_log_entry.py` now imports from it (CLI unchanged) instead of duplicating it.
3. New `scripts/governance/audit_log_coverage.py` (read-only) finds every date with a governed-file commit and no `logs/<date>.md` on disk, in a push range or full history -- the same query used during investigation, productionized.
4. New `scripts/governance/heal_log_coverage.py` -- the one script in `scripts/governance/` deliberately write- and push-capable outside a human `git commit` -- consumes those gaps and writes one `auto-skeleton`-tagged entry per date via `log_shard_writer`, self-validates via a full `validate_plan_structure.py` run before committing, and refuses (exits without writing) a batch over 5 gap dates as a circuit breaker.
5. New `.github/workflows/log-coverage-heal.yml` (push-triggered, `contents: write`) runs the healer over each push's `before..after` range -- the actual guarantee, since it runs regardless of which agent or environment made the commit and depends on no agent's compliance.
6. New `.github/workflows/log-coverage-audit.yml` (daily cron + `workflow_dispatch`) sweeps full history as a path-independent backstop, and deliberately fails the workflow loud whenever it finds anything (even after auto-healing it) -- a scheduled-sweep finding means layers 1-2 both missed something in real time and that needs investigating, not silent patching.
7. `logs/README.md`'s Maintenance section now documents this as enforced, not just conventional, and adds the `auto-skeleton` tag (`grep auto-skeleton logs/*.md` finds every entry still needing a human/agent narrative-enrichment pass).

Unit tests: `tests/unit/test_validate_plan_structure.py` (`TestGovernedEditsPairedWithLogEntry`, 8 cases via the injectable `previous_texts` seam, same pattern as `TestWaveReconciliationGate`), `tests/unit/test_audit_log_coverage.py` (6 cases via an injectable `commits` seam), `tests/unit/test_heal_log_coverage.py` (11 cases covering skeleton generation, the circuit breaker, dry-run, and a real write path -- one test caught a real `KeyError` in `_skeleton_for_gap` on a file outside the expected governed set, fixed to degrade gracefully instead of crashing an unattended CI job).

**Honest limits, not claimed unbypassable.** Without GitHub branch protection, a force-push or an Actions outage could still evade layers 1-2 simultaneously; layer 3 (the daily sweep) bounds that to one audit interval, not zero. Closing that fully would mean branch protection disallowing direct pushes to `main`, which cuts directly against decision #107's deliberate control-repo direct-push carve-out for both Claude Code and Codex -- flagged as a real, separate governance decision, deliberately not made here.

The 10 known-missing days are backfilled separately with hand-authored narrative entries (root cause, fix, commit hashes, matching `logs/2026-08-11.md`'s precedent depth per explicit user choice), not auto-skeletons -- they predate this mechanism and its skeleton format is meant for entries this system generates itself going forward, not a substitute for real investigation of history that already happened.
