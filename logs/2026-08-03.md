## Entries

- [master campaign-freeze requirements] **2026-08-03 — Sealed immutable PlanFreezeV1 and PipelineContractSnapshotV1 in place of the mutable CampaignFreezeV1.** The mutable, single `CampaignFreezeV1` binding (control HEAD, graph, registry, prompts, templates, facts, validators, etc. all in one blob) is replaced by two typed, immutable contracts in the new `src/readme_agent/supervisor/contract_freeze.py`: `PlanFreezeV1` seals only clean, already-committed governance/control bytes (control branch/commit, member file hashes, plan-set/graph hashes) with a `SEALED` status, while `PipelineContractSnapshotV1` separately materializes selected dirty/uncommitted candidate implementation bytes into a content-addressed snapshot root (`runs/pipeline-contract-snapshots/`) for read-only worker consumption, so workers never read mutable coordinator-worktree files directly. New `stage_dependencies.py` narrows each repository stage's dependency key to only the ecosystem adapter/fact family/validator family/prompt/model route/tests it actually needs, instead of the full freeze; new `campaign_evidence.py`/`campaign_packets.py` add a replayable `CampaignEvidenceManifestV1` (graph/manifest hashes, replay ID, task verdicts) so a campaign's acceptance can be independently re-derived. `scripts/governance/seal_final_throughput_contracts.py` builds and replays the seal; four new test files (`test_contract_freeze.py`, `test_campaign_evidence.py`, `test_campaign_packets.py`, `test_stage_dependency_manifest.py`) cover the new schemas. `plans/master.md`/`plans/requirements.md` (L8-016, L8-041, L8-042, L8-044) and the mission graph's `verified_baseline`/`conflicts_found` blocks are rewritten to reference the new contracts and resolve four historical plan contradictions. Commit `c8e6328f9`.
