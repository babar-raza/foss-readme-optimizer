- [fix] **2026-08-29 — Verification-baseline restoration (GOV-032/GOV-033, VER-012/VER-013)**

Baseline at HEAD `1d915e9b07b0`: `5 failed, 5498 passed`. Four root causes found and fixed; two of them

**`_inventory_valid()` under-enumerated past Windows MAX_PATH (3 tests, real product defect).**
`evidence/writer.py` seals *and* verifies a bundle through `evidence/file_inventory.py::enumerate_files()`,
which prefixes `\?\` on Windows and raises on traversal error. `supervisor/local_poc_cache.py::_inventory_valid()`
had hand-rolled a second walk with `Path.rglob("*")`, which has neither property — pathlib silently
swallows the `os.scandir` failure Win32 raises at or beyond MAX_PATH. Instrumented one run:
sealed inventory 64 entries, `rglob` saw 46, and the 18 it missed were exactly the
`review/bounded-packet-cache/*.json` files, present on disk throughout (46 + 18 = 64). Consequence:
an intact approved bundle reported `artifact_inventory_invalid`, `evaluate_approved_local_poc_cache()`
refused reuse, and **`NO_OP_PROVEN` was unreachable for exactly the repositories with the longest
names** — `win_long_path`'s own docstring records the path hitting 260 characters for
`aspose-note-foss__Aspose.Note-FOSS-for-Python`. Fixed by reusing `enumerate_files()`. New
`tests/unit/test_local_poc_cache_inventory_long_path.py` proves the long-path bundle validates, with a
negative control proving a tampered entry under the same path is still rejected.

**`persist_evaluation()` never reconciled claims (autonomy blocker).** `plans/master.md` states that
mission `evaluate` "reconciles graph drift, claims, lifecycle freshness, and component hashes", but
`_recover_expired_claim()` had exactly one caller — inside `claim_next_task()`. Because
`evaluate_mission()` computes `eligible = [] if active else _ready_tasks(...)`, any set
`active_task_id` suppresses eligibility regardless of lease validity. Found live: the authoritative
origin-backed state carried a claim by `codex-portfolio-resume` expired `2026-08-28T08:33:24Z` that
had blocked every dependency-ready task for ~23 hours, and `evaluate` would not release it. Fixed;
covered by a recovery test and a negative control proving an unexpired claim is never stolen.

**Check-battery pin drift + the CI hole that allowed it (GOV-032/GOV-033).** `d8795bbdb` edited the
vendored `readme_refresh_checks.py` without re-pinning its manifest. Re-pinned with a
`local_adaptations` entry recording why the change is match-preserving. More importantly:
`validate_pinned_hashes.py` reported **clean** throughout, because this pin is deliberately excluded
in favour of its own dedicated test — which ran only pre-commit, only for staged files, from a hook
that landed a day *after* the drift. Added `--all` to `validate_pinned_hash_dedicated_tests.py` and
wired it into CI's `pinned-hashes` job. Also replaced the `GOV-0NN` placeholders left in
`install_hooks.py`, `validate_governance_write_lock.py`, and `git_backend.py` with GOV-033.

**Producer/consumer divergence on `verified_equivalence` (VER-013).** `claim_accountability.py`
deliberately narrows such a claim's coordinates to the resolution's exact fact scope, with its own
comment warning against inflation; `claim_accountability_validation.py` re-derived a broader set and
demanded it — doing precisely what that comment warns against. The validator now applies the same
narrowing.

**Also corrected a stale test expectation and strengthened it.** `test_local_poc_records_snapshot_and_profile_before_later_stages`
asserted the merged single-call reviewer runs once; production dispatches `run_separated_readme_review()`,
so the real counts are 0 merged and 18 grounded-role calls. The "no new provider calls on an unchanged
rerun" assertions were comparing 0 to 0 and proving nothing about the reviewer that ran; they now track
the role reviewer too.
