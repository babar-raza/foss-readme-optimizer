Re-sequenced into three tiers by actual payoff speed: Tier 0 (cheap, do now), Tier 1 (cheap diagnostic, do next), Tier 2 (#111/#112 themselves, explicitly deferred, separately time-boxed). Built Tier 0 and Tier 1 on explicit instruction ("do 0 & 1").

**GOV-033 (Tier 0).** Read `git_backend.py`'s `_acquire_lock_generic`/`_release_lock_generic`/`_renew_lock_generic`/`_lock_still_held_generic` in full: a real, already-production-proven, non-blocking optimistic-CAS distributed lock, already generalized over an arbitrary key, already backing two independent families (`LOCK_REF_PREFIX`, `RUN_LOCK_REF_PREFIX`). Added a third thin wrapper — `GOVERNANCE_LOCK_REF_PREFIX`, `GOVERNANCE_LOCK_LEASE_SECONDS = 900`, `acquire_governance_lock()`/`release_governance_lock()`/`peek_governance_lock()` (the last new, needed because a failed acquire returns bare `None` with no holder detail) — rather than inventing a new mechanism. New `scripts/governance/validate_pinned_hash_dedicated_tests.py`: a declarative trigger table (today, one entry — the check-battery manifest, whose trigger paths are derived live from the manifest's own file list, not hardcoded) that runs only the specific pytest node id(s) relevant to files staged in the current commit, closing the CI-advisory hole without moving the full suite into pre-commit. New `scripts/governance/validate_governance_write_lock.py`: zero network calls when no protected path is staged; otherwise acquires the lock and lets it expire naturally rather than releasing immediately (a correction made during implementation — an immediate release would erase the very trace a concurrent session is meant to observe), or peeks and prints an informational note if already held; any backend error degrades to a soft skip, never blocking. Deliberately does not yet distinguish this session's own prior lock from a genuine peer's — Phase 1 never blocks either way, so it doesn't need to; that's explicitly deferred to a Phase 2 this work does not build. Both wired into `install_hooks.py`'s pre-commit template (dedicated-test gate blocking, governance lock not) and reinstalled locally (shared across all worktrees); proven live against this very commit. 35 new tests total across `test_governance_write_lock.py`, `test_validate_pinned_hash_dedicated_tests.py`, `test_validate_governance_write_lock.py`, and `test_install_hooks.py`.
