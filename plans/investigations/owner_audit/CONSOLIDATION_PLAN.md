# Consolidation and decision protocol

The owner will not merge agent prose by majority vote. Every material conclusion must resolve to
an inspected file, symbol, pinned repository object, committed evidence artifact, or reproducible
command.

## Questions the combined audit must answer

1. What authoritative information exists for each representative product?
2. How much was imported, and with what provenance/freshness?
3. Which imported units are parsed, accepted, offered to Qwen, rendered, and validated?
4. Where is useful specificity lost or unsupported wording introduced?
5. Which acceptance paths fail open or rely on advisory evidence?
6. Which stage owns each correction, and which downstream stages must invalidate?
7. What minimal sequence can prove one simple, one complex, and one README-only product before
   portfolio expansion?
8. What evidence is required to claim 30/30 Aspose calibration and 33/33 optimizer completion?
9. What bounded GitHub Actions execution shape fits time, memory, disk, network, and Qwen limits?

## Finding normalization

Each accepted finding will have:

- a self-explanatory slug;
- pinned input and output identities;
- observed behavior and expected contract;
- evidence paths and reproduction command;
- severity and affected scope;
- causal owner (module/function/data/prompt/contract);
- smallest repair and exact regression test;
- invalidated lifecycle stage;
- dependencies on PSD or other external evidence;
- closure condition and explicit non-claims.

## Priority order

1. False or unsupported README content.
2. Imported authoritative knowledge silently lost before visible output.
3. Existing README information omitted without evidence-backed reconciliation.
4. Acceptance paths that fail open, skip blocking checks, or misstate execution.
5. Non-deterministic hashes, stale cache reuse, or incorrect stage invalidation.
6. Qwen context/quality shortcomings and ineffective repair.
7. Cross-ecosystem and README-only coverage.
8. Runner throughput and publication isolation.

## Audit lanes

The first completed tranche contains source/knowledge truth, knowledge-to-candidate lineage,
acceptance/runner behavior, and sealed replay quality. Two follow-on read-only lanes extend it with
the all-33 portfolio input matrix and the defect-to-gate/red-test map. PSD evidence remains an
external pending input and will be reconciled separately when supplied.

## Deliverable

The final ZIP will contain this plan, the owner ledger, every completed lane report and structured
evidence, reconciled findings, the prioritized implementation sequence, reproduction notes, and a
top-level SHA-256 inventory. It is evidence for future optimizer commits, not proof that any gap has
already been fixed.
